# 머신러닝과 분류모델 평가

## 1. 머신러닝 개요

### 1.1 머신러닝이란?

- 데이터를 학습하도록 만들어진 **알고리즘**
- 사람이 컴퓨터 언어로 구현한 프로그램
- 데이터를 통해 **숨은 패턴을 학습하여 모델을 생성**

> 머신러닝 = 데이터 + 알고리즘 → 학습된 모델

#### Machine learning vs Machine learned DATA

머신이 데이터를 배우는 것이다.   
왜? 사람에 의해서 만들어지니까.

데이터만 던져주면 머신이 배우는게 아니다. 우리가 파이썬을 통해서 특정 알고리즘을 수행하고자 하고, 일련의 과정들을 통해서 기계를 학습시키는 것이기 떄문이다. 알고리즘과 컴퓨터 언어가 필요하니까!

**그래서 Machine learning이 아니라, Machine learned DATA by human이 적절하지 않을까?**

---

### 1.2 규칙 기반 AI vs 머신러닝

| 구분 | 규칙 기반 인공지능 | 머신러닝 |
|------|------------------|-----------|
| 규칙 생성 | 사람이 직접 정의 | 데이터로부터 자동 학습 |
| 예시 | "길다, 노랗다 → 바나나" | 특징을 입력하면 모델이 바나나 예측 |
| 확장성 | 낮음 | 높음 |
| 유연성 | 낮음 | 높음 |

> 규칙기반 인공지능은 사람이 정보를 알려준 것이다.  
> 머신러닝에서 바나나의 특징을 알려주지 않는다. 이것은 머신러닝 모델의 결과로써 얻어지는 부분이다. 
> 규칙을 사람이 정해주냐, 아니면 모델이 만드냐의 차이이다. 
---

### 1.3 머신러닝 모델이란?

- 데이터에 알고리즘을 적용한 결과물
- 학습 완료 후 새로운 데이터 예측 가능  
> 모델이란 알고리즘을 실행한 뒤에 얻어지는 결과이다. 

예시 (선형회귀):

\[
Y = \beta_0 + \beta_1X_1 + \cdots + \beta_pX_p
\]

# 4. 분류 모델 평가

---

## 4.1 분류 문제란?

- Y가 클래스(Label)
- Binary(이진분류 문제) / Multi-class (다중분류 또는 다항 분류 문제)

예시:
- 이직 여부 (Y/N)
- 주가 방향 (Up/Down/Neutral)

---

## 4.2 혼동행렬 (Confusion Matrix)  
*이진분류일 때 어떻게 모델을 평가할까? 즉, 정확히 말하면 이진 분류 모델의 평가이다*

### 1) 기본 구조

|               | 실제 Positive | 실제 Negative |
|--------------|---------------|---------------|
| 예측 Positive | TP | FP |
| 예측 Negative | FN | TN |

---

### 2) 주요 평가 지표

| 지표 | 수식 | 의미 |
|------|------|------|
| Accuracy(정확도) | (TP+TN) / (TP+TN+FP+FN) | 전체 중 맞춘 비율 |
| Error Rate(오분류율) | (FP+FN) / (전체) | 전체 중 틀린 비율 |
| Sensitivity (Recall) | TP / (TP+FN) | 실제 양성 중 맞춘 비율 |
| Specificity(특이도) | TN / (TN+FP) | 실제 음성 중 맞춘 비율 |
| Precision(정밀도) | TP / (TP+FP) | 예측 양성 중 실제 양성 |

#### 명칭에 대한 추가 설명 
--- 
왜 민감도라고 부를까?(또는 재현율)

이 모델이 양성에 얼마나 민감하게 반응하느냐? 이다. 즉, 진짜 양성인데 놓치면 안된다.!! 모델이 postivie 신호에 예민하게 반응하면 FN 가 줄어준다. 

📌 Positive를 감지하는 감각이 얼마나 예민한가?
→ 그래서 “민감도”

즉,

무엇에 민감?
👉 Positive 클래스에

또한, “재현”은 말 그대로

이미 존재하는 것을 다시 드러내는 것

이야.

모델이 새로운 Positive를 만드는 게 아니야.
원래 데이터 안에 이미 존재하던 Positive들을

🔎 얼마나 빠짐없이 다시 찾아냈는가?

그걸 측정하는 게 Recall이야.

의학 분야에서는

검사 시스템이 질병에 얼마나 민감하게 반응하는가?

→ Sensitivity

정보검색/머신러닝 분야에서는

실제 Positive를 얼마나 다시 찾아냈는가?

→ Recall

--- 
왜 특이도라고 부를까?  
“괜히 양성이라고 오진하지 않는 능력”

즉, Negative를 Positive로 잘못 판단하는 FP를 줄이는 능력이야.

이게 왜 “특이”냐면,

의학 용어에서 유래했어.

검사가 특정 질병에 특이적(specific) 이라는 말은:

그 병이 아닐 때는 거의 반응하지 않는다

즉,

질병이 없으면 (Negative)

괜히 양성이라고 하지 않는다

그래서

📌 Negative에 대해 잘 구별해내는 능력
→ 특정 대상에만 반응하는 성질
→ “특이도”

--- 

여기서, 민감도는

“실제 Positive 기준”

정밀도는

“예측 Positive 기준”

즉, 모델이

“양성입니다!” 라고 말한 것들 중에서
얼마나 정확했는가?

FP가 많으면,
모델이 너무 쉽게 Positive라고 외치는 거야.

그래서

📌 Positive라고 예측할 때 얼마나 신중하고 정확한가?
→ 그래서 “정밀도”

즉,

무엇이 정밀?
👉 Positive라고 선언하는 판단이 정밀한가

### 3) 예시 해석 (암 진단/ 보통 관심있는 것을 참으로 가정함) 

- Accuracy = 0.875
- Sensitivity = 0.25
- Specificity = 0.944

👉 정확도는 높지만 실제 암 환자를 잘 탐지하지 못함  
👉 의료 분야에서는 **민감도(Recall)** 가 중요

정확도 오분류율에서도 좋은 알고리즘일 수 있지만,

민감도와 특이도를 보면 또 안좋은 알고리즘으로 판별될수도 있다.

민감도가 중요한 부분이 있다. 예를 들어 코로나이다 . 정확도는 높지만, 민감도가 낮은 모델이라면? 이 모델은 코로나 테스트기 측면에서 보면 안좋은 모델인 것이다. 
의학 통계에서는 민감도가 중요하다. 특정 머신러닝에서도 민감도가 중요한 부분이 있다.   

민감도와 특이도는 서로 트레이드오프 관계가 있다. 둘 다 높게 하는 것이 어렵다.

## 4.3 Cut-off (Threshold)

- 로지스틱 회귀에서 확률 기준값
- 일반적으로 0.5 사용
- Cut-off에 따라 Accuracy가 달라짐 (0.52 ~ 0.82)

👉 임계값 조정이 중요

> 모든 cut off를 고려한 모델 평가이다! 모든 컷오프를 다 사용했을 떄에도 좋은 모델이면 좋은 모델인 것이니까. 
---

## 4.4 ROC Curve

### 개념

- 모든 threshold를 고려한 평가 방법
- X축: FPR (False Positive Rate)
- Y축: TPR (True Positive Rate)

\[
FPR = \frac{FP}{TN+FP}
\]

\[
TPR = \frac{TP}{TP+FN}
\]

### 목표

> TPR은 높이고, FPR은 낮추는 것

---

## 4.5 AUC (Area Under Curve)

| AUC 값 | 의미 |
|--------|------|
| 1 | 완벽한 모델 |
| 0.5 | 랜덤 모델 |

👉 모델 비교 시 Accuracy보다 AUC가 더 안정적
> 여기서 curve가 ROC를 의미한다. 즉, AUC는 ROC 커브의 밑의 면적을 의미하는 것이다.

## 5. 유사도와 거리

### 5.1 유클리디안 거리

\[
D(x,y)=\sqrt{\sum (x_i-y_i)^2}
\]

- 변수 간 상관관계 고려하지 않음

---

### 5.2 마할라노비스 거리

\[
D(x,y)=(x-y)^T S^{-1}(x-y)
\]

- 공분산 행렬 S를 고려
- 변수 스케일과 상관성 반영

    변수간의 관계를 보자. 사실 노란색과 빨간색의 관계가 파란 색과 빨간색의 관계보다 더 관계가 있다면? ㅁ눈으로 보았을 떄 똑같은 거리 즉, 유클리디안 거리가 똑같아도 사실 노란색 점이 훨씬 더 멀리 떨어진 것일 수 있다는 사실이다!


#### 그럼 변수 간의 관계란 무엇인가? 
그럼 ‘변수 간의 관계’란 무엇인가?
👉 1) 상관관계 (Correlation)

예를 들어:

키와 몸무게

소득과 소비

수학 점수와 물리 점수

이런 변수들은 보통 같이 움직여.

즉,

키가 크면 몸무게도 같이 증가하는 경향

이게 바로 상관성이야.

공분산 행렬 S 안에는:

각 변수의 분산 (대각선)

변수 간 공분산 (비대각선)

이 들어 있어.

👉 2) 스케일 차이 (Scale difference)

예를 들어:

키: 150~190

연봉: 2000~1억

숫자 단위 차이가 엄청 크지?

유클리디안 거리는
숫자가 큰 변수가 거리를 거의 지배해버려.

하지만 마할라노비스 거리는

분산이 큰 방향은 “덜 중요한 변화”로 보고
분산이 작은 방향은 “더 중요한 변화”로 본다

즉,

많이 퍼져 있는 방향은 덜 민감

좁게 몰려 있는 방향은 더 민감

📌 두 변수 간의 관계 = 무엇을 의미하나?

✔ 서로 얼마나 같이 움직이는가 (상관성)
✔ 각 방향으로 얼마나 퍼져 있는가 (분산)

즉,

변수들이 독립적인가?
아니면 어떤 방향으로 함께 움직이는가?

이걸 반영하는 게 공분산 행렬 S야.

## 6. 변수 표준화와 정규화

### 6.1 필요성

- 변수 단위가 다르면 거리 왜곡 발생
- 거리 기반 모델에서 필수적 전처리

> 똑같은 유클리디안 거리인데, 단위가 붙으니까 갑자기 거리가 엄청 나는 것처럼 보인다. 또한, 거리가 큰 것도 바뀌게 된다.

> 그렇기 떄문에 우리는 거리를 기준으로 분류하는 모델은 변수 표준화 정규화가 꼭 필요하다. 
---

### 6.2 표준화 (Standardization)  
*데이터가 평균에서 어느정도 떨어져 있느냐? 이다.*

\[
x_{new} = \frac{x-\mu}{\sigma}
\]

- 평균 0, 표준편차 1
- KNN, SVM 등 거리 기반 모델에 사용
- 릿지 라쏘는 표준화를 시키지 않으면, 패널티가 변수마다 불공정하게 적용된다. 그래서 표준화를 해줘야 모든 변수에 동일한 기준으로(단위 상관 없이) 패널티가 적용된다. 
---

### 6.3 정규화 (Normalization)

\[
x_{new} = \frac{x-x_{min}}{x_{max}-x_{min}}
\]

- 범위 [0,1]
- 이미지 분석 등에서 사용

- 변수 스케일 차이 → 성능 왜곡
