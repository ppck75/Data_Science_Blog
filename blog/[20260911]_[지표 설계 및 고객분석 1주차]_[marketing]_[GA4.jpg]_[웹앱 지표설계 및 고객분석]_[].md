## 지표 설계의 중요성 
생성형 AI가 데이터 분석 워크플로우에 들어왔다. 모든 업무가 대체되는가? 아니다. 자동화의 영향은 모든 업무 단계에 고르게 퍼져 있지 않는다. 

문제정의, 분석 설계, 커뮤니케이션(비즈니스 해석)은 거의 영향을 받지 않았다. **정의가 틀리면 자동화는 틀린 답을 더 빠르게 생산한다** 그러므로, 샐행속도가 빨라질 수록, AI가 발전할 수록 '정의'의 중요도는 오히려 올라간다. 그러므로 도구가 아니라 **지표설계**에서 출발해야 하는 이유이다.

## GA4란 무엇인가?
GA4란 **웹/앱에서 발생하는 사용자 행동을 이벤트 단위로 수집 및 집계하는 분석 도구이다**

여기서 알 수 있는 것은,  
1. 웹 앱을 하나의 속성에서 다룬다. 
2. 모든 행동을 이벤트로 환원한다 (페이지 조회, 스크롤, 구매가 전부 같은 자료형이다)

GA4의 주 사용처는 웹 앱 지원, 마케팅 성과 측정에 있다. (Amplitude는 프로덕트 중심이라고 한다면)

또한, BigQuery 연동으로 이벤트 단위 조회가 가능하다. 


-> 결론적으로 GA4는 어디서 들어와서 얼마를 샀는가?를 보는데에 강하다. 

## 이벤트 태깅

사용자 행동 로그 데이터는 1. 집계되지 않은 원본이며 2. 저절로 쌓이지 않고(사전에 무엇을 남길 것인지 정의가 필요함) 3. 행동은 기록하되 이유는 기록하지 않는다(즉, 왜 이탈했는지 모른다. 이건 해석가의 몫이다)

-> 여기서 GTM을 통해 이벤트를 설계하고 태깅하여 어떤 로그 데이터를 수집할지 정의하는 과정이 들어간다!

GA4는 이벤트 기반 데이터 모델이다. 행동을 단일 이벤트로 기록한다. 
*purcahse 이벤트 하나에 currency, items, value 등.. 매개변수를 각각 붙이는 식이다*

이벤트가 있고, **주요 이벤트(key event)**가 있다. 주요 이벤트란 비즈니스 목표 달성에 중요하다고 표시한 이벤트를 의미한다. 

    이벤트(웹 앱에서 발생하는 모든 사용자 행동) -> 주요 이벤트 -> 전환(광고 캠페인의 성과 측정에 쓰임)


## GA4 데이터의 4단계 흐름


웹/앱 -> GTM(이벤트 설계 및 태그발행) -> GA4(수집, 처리, 표준 보고서) -> BigQuery(원시 이벤트 적재 SQL) -> Looker Studio(대시보드 공유) 


## GA4 보고서 

GA4에 연결하여 보고서 탭에 들어가면 보고서 개요, 실시간 개요, 실시간 페이지를 확인 가능하다. 정형화된 표준 보고서로, GA4에서 가장 많이 쓰이는 메뉴이다. 

좌측에는 획득(사용자가 어디서 들어왔는가), 참여도(무엇을 했는가), 수익 창출(얼마를 벌었는가), 유지(다시 돌아왔는가), 사용자(사용자가 누구인가)를 볼 수 있다. 

-> 각각 화면에 들어가서 웹사이트에 관한 여러 대시보드를 확인 가능하다!!
