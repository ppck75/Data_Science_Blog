# Docker란?

개발을 하다 보면 "내 컴퓨터에서는 되는데 다른 사람 컴퓨터에서는 안 된다"는 상황을 자주 만나게 된다.  
이런 문제는 운영체제, 라이브러리 버전, 런타임 환경, 설정 파일 차이에서 주로 발생한다.

Docker는 이런 차이를 줄이기 위해 등장한 도구다.  
애플리케이션을 실행하는 데 필요한 환경을 하나의 단위로 묶어서, 어디서든 비슷한 방식으로 실행할 수 있게 해준다.

## 왜 Docker를 사용할까?

Docker를 사용하지 않으면 팀원마다 개발 환경이 달라질 수 있다.  
예를 들어 누군가는 Python 3.10을 쓰고, 누군가는 3.12를 쓰고, 또 다른 사람은 라이브러리 버전이 조금 다를 수 있다.  
이런 차이는 작은 오류부터 큰 실행 문제까지 이어질 수 있다.

Docker를 사용하면 애플리케이션 실행에 필요한 환경을 컨테이너로 통일할 수 있다.  
즉, 여러 개발자가 같은 기준의 환경에서 작업할 수 있게 해주는 것이다.

## 이미지와 컨테이너

Docker를 이해할 때 가장 먼저 구분해야 하는 개념은 `이미지(Image)`와 `컨테이너(Container)`다.

이미지는 특정 프로그램을 실행하는 데 필요한 요소를 묶어 둔 설계도다.  
코드, 런타임, 라이브러리, 환경 설정 등이 포함된 실행 패키지라고 보면 된다.

컨테이너는 그 이미지를 실제로 실행한 상태다.  
즉, 이미지는 정적인 파일이고 컨테이너는 실제로 움직이는 프로세스다.

정리하면 다음과 같다.

> Docker 이미지: 실행 환경을 묶어 둔 정적인 패키지  
> Docker 컨테이너: 이미지를 실행해서 동작 중인 상태

## Docker 기본 명령어

자주 사용하는 Docker 기본 명령어를 먼저 정리해보자.

### 1. Docker 버전 확인

```bash
docker --version
```

예시 출력:

```text
Docker version 29.3.0, build 5927d80
```

현재 설치된 Docker 버전을 확인할 때 사용한다.

### 2. Docker 상세 정보 확인

```bash
docker info
```

Docker 엔진 상태, 저장소 위치, 컨테이너 수, 이미지 수 등 상세 정보를 확인할 수 있다.

### 3. 현재 보유한 이미지 확인

```bash
docker images
```

이 명령어를 실행하면 현재 로컬 환경에 저장된 이미지 목록이 표시된다.  
아직 내려받은 이미지가 없다면 목록이 비어 있을 수 있다.

### 4. 실행 중인 컨테이너 확인

```bash
docker ps
```

현재 실행 중인 컨테이너만 확인할 수 있다.

실행이 종료된 컨테이너까지 모두 보고 싶다면 아래 명령어를 사용한다.

```bash
docker ps -a
```

즉, `docker ps`는 실행 중인 컨테이너만, `docker ps -a`는 전체 컨테이너를 보여준다.

## `docker run` 이해하기

`docker run`은 이미지를 기반으로 새로운 컨테이너를 생성하고 실행하는 명령어다.

예를 들어 아래 명령어를 실행한다고 가정해보자.

```bash
docker run -d -p 8080:80 --name my-nginx nginx
```

각 옵션의 의미는 다음과 같다.

- `docker run`: 새 컨테이너를 생성하고 실행한다.
- `-d`: 컨테이너를 백그라운드에서 실행한다.
- `-p 8080:80`: 호스트의 `8080` 포트를 컨테이너의 `80` 포트에 연결한다.
- `--name my-nginx`: 컨테이너 이름을 `my-nginx`로 지정한다.
- `nginx`: 사용할 이미지 이름이다.

이 명령어를 실행하면 Nginx 웹 서버 컨테이너가 생성되고 실행된다.  
이후 브라우저에서 `http://localhost:8080`으로 접속하면 Nginx 화면을 확인할 수 있다.

실행 후 `docker ps`를 입력하면 보통 아래와 비슷한 형태로 출력된다.

```text
CONTAINER ID   IMAGE   COMMAND                  CREATED         STATUS         PORTS                                   NAMES
791a15d1d733   nginx   "/docker-entrypoint.…"  6 minutes ago   Up 6 minutes   0.0.0.0:8080->80/tcp, [::]:8080->80/tcp my-nginx
```

즉, 이미지를 내려받는 것에서 끝나는 것이 아니라, 그 이미지를 기반으로 실제 실행 중인 컨테이너가 생긴다는 점이 중요하다.

## Docker는 어떻게 활용할까?

Docker에서는 내가 직접 만든 애플리케이션을 이미지로 만들어 실행할 수도 있고,  
`nginx`, `redis`처럼 이미 잘 만들어진 공식 이미지를 가져와서 바로 사용할 수도 있다.

이 방식의 장점은 분명하다.

- 실행 환경을 표준화할 수 있다.
- 협업 시 환경 차이로 인한 문제를 줄일 수 있다.
- 로컬, 테스트, 배포 환경을 비슷한 방식으로 맞출 수 있다.

## `prune` 명령어는 주의해서 사용하기

Docker를 사용하다 보면 쓰지 않는 이미지, 중지된 컨테이너, 불필요한 리소스가 쌓이게 된다.  
이럴 때 사용하는 명령어가 `prune`이다.

다만 `prune`은 삭제 명령어이기 때문에 신중하게 사용해야 한다.

자주 보게 되는 명령어는 다음과 같다.

```bash
docker image prune
docker image prune -a
docker system prune
docker system prune --volumes
```

각 명령어는 사용하지 않는 이미지나 시스템 리소스, 볼륨 등을 정리한다.  
특히 `-a` 옵션이나 `--volumes` 옵션은 삭제 범위가 넓기 때문에, 현재 필요한 리소스가 없는지 먼저 확인한 뒤 실행하는 것이 좋다.

## 마무리

Docker는 단순히 "컨테이너를 띄우는 도구"가 아니라,  
개발 환경을 표준화하고 협업 효율을 높이기 위한 중요한 기반 도구다.

처음에는 이미지와 컨테이너의 차이, 그리고 몇 가지 기본 명령어만 이해해도 충분하다.  
그 다음부터는 직접 컨테이너를 실행해보면서 `docker run`, `docker ps`, `docker images` 같은 명령어에 익숙해지는 것이 가장 빠른 학습 방법이다.
